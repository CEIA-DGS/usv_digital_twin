The type used to store JSON numbers (integers).

\href{https://tools.ietf.org/html/rfc8259}{\texttt{ RFC 8259}} describes numbers as follows\+: \begin{quote}
The representation of numbers is similar to that used in most programming languages. A number is represented in base 10 using decimal digits. It contains an integer component that may be prefixed with an optional minus sign, which may be followed by a fraction part and/or an exponent part. Leading zeros are not allowed. (...) Numeric values that cannot be represented in the grammar below (such as Infinity and NaN) are not permitted. \end{quote}
This description includes both integer and floating-\/point numbers. However, C++ allows more precise storage if it is known whether the number is a signed integer, an unsigned integer or a floating-\/point number. Therefore, three different types, {\ttfamily number\+\_\+integer\+\_\+t}, \doxysectlink{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__unsigned__t}{\`{}number\+\_\+unsigned\+\_\+t\`{}}{0} and \doxysectlink{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__float__t}{\`{}number\+\_\+float\+\_\+t\`{}}{0} are used.

To store integer numbers in C++, a type is defined by the template parameter {\ttfamily Number\+Integer\+Type} which chooses the type to use.\hypertarget{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__integer__t_autotoc_md585}{}\doxysection{\texorpdfstring{Notes}{Notes}}\label{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__integer__t_autotoc_md585}

With the default values for {\ttfamily Number\+Integer\+Type} ({\ttfamily std\+::int64\+\_\+t}), the default value for {\ttfamily number\+\_\+integer\+\_\+t} is {\ttfamily \#!cpp std\+::int64\+\_\+t}.\hypertarget{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__integer__t_autotoc_md587}{}\doxysubsubsection{\texorpdfstring{Default behavior}{Default behavior}}\label{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__integer__t_autotoc_md587}

\begin{DoxyItemize}
\item The restrictions about leading zeros is not enforced in C++. Instead, leading zeros in integer literals lead to an interpretation as octal number. Internally, the value will be stored as decimal number. For instance, the C++ integer literal {\ttfamily 010} will be serialized to {\ttfamily 8}. During deserialization, leading zeros yield an error.
\item Not-\/a-\/number (NaN) values will be serialized to {\ttfamily null}.
\end{DoxyItemize}\hypertarget{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__integer__t_autotoc_md588}{}\doxysubsubsection{\texorpdfstring{Limits}{Limits}}\label{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__integer__t_autotoc_md588}
\href{https://tools.ietf.org/html/rfc8259}{\texttt{ RFC 8259}} specifies\+: \begin{quote}
An implementation may set limits on the range and precision of numbers. \end{quote}
When the default type is used, the maximal integer number that can be stored is {\ttfamily 9223372036854775807} (INT64\+\_\+\+MAX) and the minimal integer number that can be stored is {\ttfamily -\/9223372036854775808} (INT64\+\_\+\+MIN). Integer numbers that are out of range will yield over/underflow when used in a constructor. During deserialization, too large or small integer numbers will be automatically be stored as \doxysectlink{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__unsigned__t}{\`{}number\+\_\+unsigned\+\_\+t\`{}}{0} or \doxysectlink{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__float__t}{\`{}number\+\_\+float\+\_\+t\`{}}{0}.

\href{https://tools.ietf.org/html/rfc8259}{\texttt{ RFC 8259}} further states\+: \begin{quote}
Note that when such software is used, numbers that are integers and are in the range \$\mbox{[}-\/2\texorpdfstring{$^\wedge$}{\string^}\{53\}+1, 2\texorpdfstring{$^\wedge$}{\string^}\{53\}-\/1\mbox{]}\$ are interoperable in the sense that implementations will agree exactly on their numeric values. \end{quote}
As this range is a subrange of the exactly supported range \mbox{[}INT64\+\_\+\+MIN, INT64\+\_\+\+MAX\mbox{]}, this class\textquotesingle{}s integer type is interoperable.\hypertarget{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__integer__t_autotoc_md589}{}\doxysubsubsection{\texorpdfstring{Storage}{Storage}}\label{md_build_2dt__core_2__deps_2nlohmann__json-src_2docs_2mkdocs_2docs_2api_2basic__json_2number__integer__t_autotoc_md589}
